# Repository instructions

## Pull requests

- Include at least one Mermaid UML diagram in every pull request description. Use a sequence diagram for behavior, a state diagram for state changes, or a class diagram for structural relationships. For documentation or configuration changes, diagram the workflow the change affects.
- Keep each diagram focused on the changed behavior or workflow. Use names that reviewers can trace to the code or files.
- Add a verification section with the checks you ran and their results. Before requesting review, verify that the diagram parses and matches the change. Check the pull request preview when available.
